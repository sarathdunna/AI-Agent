# API Documentation

Base URL: `http://localhost:8000/api`. Interactive Swagger UI is available at
`http://localhost:8000/docs` (auto-generated by FastAPI from the same code).

## Health

- `GET /health` → `{"status": "ok"}`

## Datasets

- `POST /datasets/upload` (multipart `file`) → dataset metadata
- `GET /datasets` → list of datasets
- `GET /datasets/{id}` → one dataset's metadata
- `GET /datasets/{id}/preview?limit=50` → column list + row preview
- `GET /datasets/{id}/profile` → profiling agent output
- `POST /datasets/{id}/clean` (body: list of cleaning steps) → cleaning log + preview
- `GET /datasets/{id}/cleaning-log` → stored cleaning log
- `GET /datasets/{id}/eda` → EDA agent output
- `POST /datasets/{id}/visualize` (body: `{chart_type, x, y, bins}`) → chart JSON + interpretation
- `GET /datasets/{id}/dashboard` → BI KPI summary
- `GET /datasets/{id}/insights` → deterministic fact list

## Query / SQL / Pandas

- `POST /datasets/{id}/ask` (body: `{question}`) → NL answer with SQL, table, chart, explanation
- `POST /datasets/{id}/sql` (body: `{question}` or `{sql}`) → SQL result (read-only enforced)
- `POST /datasets/{id}/pandas-op` (body: `PandasOpRequest`) → result table + equivalent Python code

## Machine Learning

- `GET /ml/problem-type?dataset_id=&target=` → detected problem type + explanation
- `GET /ml/algorithms?problem_type=` → recommended algorithms with pros/cons/assumptions
- `POST /ml/train` (body: `TrainRequest`) → trained model id + metrics
- `GET /ml/models?dataset_id=` → list trained models
- `GET /ml/models/{id}` → one model's metadata
- `POST /ml/models/{id}/predict` (body: `{input: {...}}`) → single prediction
- `POST /ml/models/{id}/predict-batch` (multipart `file`) → batch predictions
- `GET /ml/models/{id}/importance` → feature importance + explanation

## Knowledge & Reports

- `POST /knowledge/ask` (body: `{question}`) → RAG answer + source docs
- `POST /reports/generate` (body: `{dataset_id, model_id?}`) → PDF file download

## Error format

All errors return `{"detail": "<message>"}`. Validation/user errors use
4xx status codes with a specific, safe message. Any unexpected server error
returns HTTP 500 with a generic message; the real exception is logged
server-side only, never sent to the client.

## SQL safety

`/datasets/{id}/sql` and the SQL agent enforce: only `SELECT`/`WITH`
statements are accepted, only one statement per request (no `;`-separated
stacking), and a keyword blocklist
(`DROP, DELETE, UPDATE, INSERT, ALTER, TRUNCATE, ATTACH, DETACH, COPY,
CREATE, REPLACE, GRANT, REVOKE, PRAGMA, CALL, EXEC, EXECUTE, VACUUM, EXPORT,
IMPORT`) is checked as a defense-in-depth layer on top of the allowlist.
